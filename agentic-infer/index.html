技术范围 / END-TO-END REQUEST PATH

Agent 工作负载特征与分层优化范围

多轮请求具有长公共前缀、增量输入、工具等待及分支并发等特征，优化目标是降低任务关键路径上的推理与状态管理开销。

  • 输入增量与历史长度不对称系统提示、工具定义及累积历史构成可复用前缀。原文 42 次调用样本的缓存 token 读写比约 11.7，说明跨轮复用占比较高。
  • 计算活动与状态生命周期解耦工具等待期间会话仍然有效；并行分支可能分布于多个 worker；分支终止后，私有 KV 的保留需求随之变化。
  • Harness、Dynamo 与推理引擎的职责边界Harness 管理任务依赖与工具；Dynamo 负责请求接入、路由及缓存协同；vLLM / SGLang / TRT-LLM 执行模型并管理引擎 KV。
问题与方案分组P1：请求语义；P2：放置与调度；P3：KV 可访问性；P4：恢复延迟；P5：保留与回收。各问题后接对应的 S 编号方案。
主线与术语：Agentic Inference · 引言。Prefill 处理输入并构建 KV；Decode 基于 KV 逐步生成。

问题 P1 / FRONTEND

请求接口中的内容语义与任务元数据缺失

Agent 请求同时包含结构化交互历史与工作流依赖；协议转换和元数据缺省会分别影响语义一致性与服务端决策。

  • 跨协议内容表示存在差异reasoning、tool call、调用标识与工具结果的组织方式依赖 API 和模型模板；不完整的转换可能破坏多轮工具调用关联。
  • 序列化差异降低前缀复用率tool schema 顺序、模板参数或历史渲染变化可能改变 token 序列。语义等价的历史并不必然具有相同的 KV 前缀。
  • 服务端缺少任务级决策依据仅根据输入 token 难以识别关键分支、预期输出长度和下一轮启动意图；这些信息主要由 Harness 掌握。
影响工具调用关联错误、前缀缓存失配，以及调度和负载估计缺少任务信息。对应方案：S1.1 协议归一；S1.2 Agent Hints。
依据：Multi-Protocol Support · Agent Hints

方案 S1.1 / FRONTEND · 对应 P1 已支持

多协议归一与交互历史一致性

通过共同内部表示、模型专用解析器与稳定的历史序列化，保留结构化内容并维持可复用的 token 前缀。

  • 多协议映射至共同处理链路Dynamo 接入 Chat Completions、Responses、Messages；后两者以类型化内容块表达交错输出，前者同样支持独立工具调用字段。
  • 模型专用解析与调用关联维护前端与 parser 将模型输出解析为工具调用、推理和文本；保留调用标识及工具结果关联，维持 Harness 的执行语义。
  • 稳定公共前缀的序列化过程应用侧固定 tool schema 顺序及模板参数；思考块保留遵循模型模板约束，降低历史渲染变化导致的缓存失配。
能力边界内容类型识别提供语义基础，但不等同于按内容类型自动实施 KV 保留策略。
原文：Layer 1 · Multi-Protocol Support。稳定前缀属于应用侧协同实践。

方案 S1.2 / FRONTEND · 对应 P1 Agent Hints 已支持

通过 Agent Hints 传递任务级元数据

Harness 将关键路径重要性、预期输出长度及续轮预热意图编码为请求扩展，供路由器、引擎与预处理链路使用。

  • priority：关键路径重要性为关键依赖分支设置较高优先级，经 Dynamo 传递至路由器与引擎；对外语义统一为数值越高、优先级越高。
  • osl：预期输出 token 数按工具调用或任务类型估计生成长度，用于负载估计，而非替代 max_tokens。启用输出块跟踪后，可进一步结合生成进度。
  • speculative_prefill：续轮前缀预热当前回复完成后，提前计算可预测的下一轮前缀。该计算路径与已有 KV 的跨层预取不同，详见方案 S4.1。
接口边界Hints 不提供资源保证或完整生命周期协议；会话身份通过 X-Dynamo-Session-ID 请求头传递，而非 agent_hints 字段。
原文：Agent Hints · 行为核对：nvext 参考

问题 P2 / ROUTER

请求级负载均衡与任务级延迟目标不一致

Agent 请求具有前缀局部性和分支依赖；仅以请求数量或即时负载选择 worker，无法充分反映任务完成时间。

  • 无缓存感知的分发增加冗余 Prefill续轮输入通常复用大部分历史。若目标 worker 缺少前缀 KV，即使即时负载较低，也可能承担显著的历史重算开销。
  • 统一队列未区分任务依赖关键分支与后台探索共享排队资源，关键请求的等待会沿依赖链传递；局部吞吐最优不等于任务完成时间最短。
  • 工作负载异构性限制固定策略串行多轮依赖缓存亲和，并行 fan-out 需要控制热点，长上下文受容量约束；单一权重难以覆盖不同任务阶段。
决策冲突缓存局部性、排队延迟与任务依赖需联合考虑。对应方案：S2.1 KV 感知放置；S2.2 优先级调度；S2.3 工作负载适配。
依据：KV-Aware Placement · Priority Scheduling · Workload Routing Strategies

方案 S2.1 / ROUTER · 对应 P2 已支持 · 需缓存信息

KV 感知放置：联合评估前缀复用与计算负载

基于 worker 的缓存状态及活跃负载估计候选执行代价，降低续轮请求的未缓存 Prefill 工作量，同时限制热点排队。

  • 事件驱动的缓存位置索引worker 发布 KV 事件，Indexer 维护块 / 前缀索引；路由器对输入分块，并查询各 worker 的可复用前缀重叠。
  • 缓存抵扣与活跃负载联合评分命中前缀抵扣未缓存 Prefill 工作量；同时计入活跃 Prefill 与 Decode 压力，降低缓存热点导致的请求集中。
  • 以执行代价而非单一命中率为目标高命中 worker 的队列成本可能抵消复用收益。通过请求级负载记账及缓存权重调整，适配不同输入长度和并发水平。
架构边界Indexer 保存 KV 位置元数据；worker / 存储层保存实际 KV。索引命中仍受状态时效性与后端可加载能力约束。
原文：KV-Aware Placement · 代价模型 · 源码入口

方案 S2.2 / ROUTER · 对应 P2 依赖队列策略与后端配置

关键路径优先级的跨队列传递

将 Harness 标注的任务重要性传递至路由队列与引擎调度器，减少关键分支排队对任务完成时间的影响。

  • 请求优先级的统一表示Harness 在请求中设置 priority；Dynamo 统一外部数值方向，并适配不同后端的优先级语义。
  • 路由与引擎调度的信号一致性支持优先级的路由队列调整请求顺序，并向后端转换、透传该信号，避免仅在入口排序而未影响引擎侧等待。
  • 队列策略与后端配置约束FCFS / WSPT 队列可利用 priority；EDF 按截止时间排序。SGLang / vLLM 等后端需显式启用相应优先级调度。
边界优先级不等于全局严格执行顺序，也不保证抢占已运行工作；需避免后台探索长期饥饿。缓存淘汰的优先级另在第三层说明。
原文：Priority Scheduling · 行为与后端要求：priority 参考

方案 S2.3 / ROUTER · 对应 P2 策略可扩展

面向工作负载特征的路由策略适配

结合会话连续性、并发分支数量和上下文容量约束，调整缓存亲和、负载分散及 worker 选择策略。

  • 串行多轮：增强会话亲和编码 Agent 持续扩展相同前缀，可提高缓存局部性的权重；故障、热点或容量压力下仍需支持重新放置。
  • 并行 fan-out：联合分散与共享高并发分支需要避免单 worker 热点；在共享前缀可加载的条件下分散执行，而非为局部命中强制集中所有分支。
  • 长上下文：优先满足容量约束先确认候选 worker 可承载任务状态，再比较缓存和负载。KvRouter 扩展接口允许引入会话信息与自定义选择逻辑。
实现入口get_potential_loads() 观察候选负载，best_worker() 查询选择，generate() 分发。NAT 在线学习路由是原文扩展示例，不是默认收益保证。
原文：Agentic Workload Routing Strategies · 策略扩展源码

问题 P3 / KV CACHE · 状态可访问性

KV 局部驻留与跨请求状态复用的冲突

Agent 的上下文生命周期跨越工具等待、子任务分叉和相邻轮次，而本地 KV 的可访问范围通常受 worker 与显存容量限制。

  • 暂停会话与活跃请求竞争显存工具等待期间 KV 仍可能被后续使用；持续驻留占用 HBM，直接淘汰则将状态保留成本转化为下一轮 Prefill 重算。
  • 子 Agent 分布导致公共前缀重复计算父任务持有的系统提示与工具定义 KV，可能无法被其他 worker 上的子任务访问；局部缓存命中无法直接扩展为跨节点复用。
  • P/D 分离造成跨轮状态位置变化Prefill 产生输入前缀 P，Decode 产生新增后缀 Δ；下一轮 Prefill 需要 P + Δ，但单轮 P→D 传输未覆盖反向复用路径。
约束已计算 KV 不等同于目标 worker 可访问的 KV。对应方案：S3.1 分层共享；S3.2 公共前缀复用；S3.3 P/D 跨轮状态发布。
依据：KV Cache as a Shared Resource · 分层、子 Agent 与 P/D 多轮状态

方案 S3.1 / KV CACHE · 对应 P3 依赖后端与存储集成

分层存储与共享 KV 资源管理

将 KV 保留周期与 GPU 驻留周期解耦，通过分层存储、块注册和加载路径扩展跨请求、跨 worker 的复用范围。

  • 按访问阶段调整存储层级活跃 KV 驻留 GPU；暂停会话的 KV 可卸载至 pinned DRAM、NVMe 或远端层，在释放显存的同时保留可恢复副本。
  • 基于前缀身份的注册与去重原文以 HiCache / KVBM 说明写穿与共享注册方向：按 sequence hash 去重，已注册的不可变块可由具备访问能力的 worker 加载。
  • 位置发现、数据持久化与传输协同索引维护位置元数据，存储提供可读副本，NIXL 等路径执行数据传输；路由选择必须与后端实际加载能力匹配。
能力边界四层为原文参考架构，并非默认部署能力；写穿、注册与跨 worker 共享语义取决于引擎及连接器集成。
原文：KV Cache as a Shared Resource · 分层与共享

方案 S3.2 / KV CACHE · 对应 P3 需要跨 worker 共享集成

子 Agent 的公共前缀跨 worker 复用

将父任务已计算的公共前缀发布至可访问的共享层，减少并行子任务冷启动时的重复 Prefill。

  • 区分公共前缀与分支私有后缀以公共系统提示和工具定义作为共享候选；子任务在命中公共部分后，对任务描述、检索结果及新增历史进行增量计算。
  • 查询、加载与增量 Prefill 衔接公共块注册到共享层，目标 worker 获取可加载前缀并恢复 KV；未命中或未覆盖的后缀仍需执行 Prefill。
  • 连续前缀与缓存兼容性约束复用要求模型、模板、KV 格式及缓存域兼容，且 token 前缀连续一致。不同前文下的相同工具文本不能直接拼接其 KV。
收益范围在公共块可用期间，以加载替代重复 Prefill；收益限定于命中的公共前缀，需计入私有后缀计算及数据传输成本。
原文：共享 KV 与子 Agent 冷启动 · 连续可加载前缀的源码表示

方案 S3.3 / KV CACHE · 对应 P3 面向 P/D 多轮的集成目标

P/D 分离下的跨轮 KV 发布与加载

将 Decode 阶段生成的 KV 后缀纳入共享发布路径，使后续 Prefill worker 能复用上一轮的完整连续历史。

  • 保留单轮 P→D 的输入前缀传输Prefill worker 计算前缀 P，经 NIXL / 后端传输至 Decode；Decode 基于 P 生成响应，并形成新增 KV 后缀 Δ。
  • 发布 Decode 新增块及位置元数据原文提出由 Decode 将新增块写入公共层，使 P 与 Δ 构成可查询、可加载的连续历史，而非仅保留在生成节点。
  • 续轮加载历史并计算新增输入下一轮 Prefill worker 加载 P + Δ，对工具结果执行增量计算。加载范围仍需与实际渲染后的 token 前缀及已发布块匹配。
集成边界单轮 P→D 传输与跨轮 D→P 复用是不同路径；后者依赖新增块发布、写入可见性及目标 worker 加载能力。
原文：共享 KV 与 disaggregated serving 的多轮状态

问题 P4 / KV CACHE · 状态恢复延迟

按需恢复将状态准备串行化至任务关键路径

跨层保留保证 KV 可恢复，但若状态准备由下一轮请求触发，数据加载和未命中前缀计算仍会延迟后续推理。

  • 非 GPU 驻留状态存在加载成本CPU、NVMe 或远端副本需要经传输路径恢复至 GPU；仅确认缓存存在，不能消除带宽、I/O 排队和加载延迟。
  • 可预测前缀仍可能缺少 KV上一轮输出与模板生成的续轮前缀未必全部处于可复用缓存中；缺失部分需要计算，与已有块的传输是不同开销。
  • 工具等待窗口未用于状态准备若加载与计算均在工具返回后启动，其成本将进入恢复路径；同时，工具耗时变化和任务提前终止限制了恢复时机预测。
优化目标减少状态准备与工具执行之间的串行依赖，而非仅增加缓存容量。对应方案：S4.1 前缀预热与跨层预取。
依据：KV Cache as a Shared Resource · Prefetch · Speculative Prefill

方案 S4.1 / KV CACHE · 对应 P4 前缀预热已支持 · 跨层预取钩子演进中

工具等待窗口内的前缀预热与 KV 预取

利用工具执行与模型请求之间的时间窗口，分别提前计算可预测前缀、恢复已有 KV，降低续轮状态准备的暴露延迟。

  • 跨层预取：恢复已有 KVHarness 可根据工具耗时分布预测续轮到达时机，提前将已有 KV 从存储层加载至 GPU；通用 Harness 预取钩子仍属演进方向。
  • speculative_prefill：计算预测前缀当前回复完成后重建、渲染并 tokenize 预测前缀，发送 max_tokens=1 的预热请求；该机制不是跨层数据传输接口。
  • 限制预测偏差与资源干扰未知工具结果不在预计算范围内；模板变化、任务终止及过早恢复均可能产生无效开销，需要约束并发、超时和前台干扰。
机制区分预热针对缺失 KV 的计算；预取针对已有 KV 的传输。二者共享时间窗口，但触发条件、资源成本和实现状态不同。
原文：工具等待与 Prefetch · 当前预热语义 · 预热源码

问题 P5 / KV CACHE · 保留与回收

访问近期性与实际复用价值不一致

LRU 主要依据最近访问时间，缺少任务重要性与会话生命周期信息，难以区分暂停会话的有效状态和已终止分支的临时状态。

  • 暂停导致高复用前缀被提前淘汰原文讨论 2–30 秒工具等待：系统提示与会话历史仍有后续访问需求，但可能因近期访问减少而被其他请求替换。
  • 近期生成不等同于后续复用子 Agent 终止或历史压缩后，部分私有 KV 不再参与后续输入；继续保留或写入低层存储将占用容量与传输带宽。
  • 请求完成无法确定会话状态失效同一会话包含多个请求，共享前缀也可能被其他 Agent 引用。仅依据请求结束事件，无法确定安全回收范围。
目标同时降低有效状态的过早淘汰与失效状态的过度保留。对应方案：S5.1 选择性保留；S5.2 生命周期驱动回收。
依据：The Problem with Uniform Eviction · Agent Lifecycle Awareness

方案 S5.1 / KV CACHE · 对应 P5 请求优先级可用 · 细粒度跨层控制演进中

基于优先级与保留意图的选择性淘汰

在访问近期性之外引入重要性与保留元数据，区分常规缓存和高复用状态，并在支持的后端中调整淘汰顺序。

  • 现有能力：请求优先级参与缓存淘汰nvext.agent_hints.priority 可被支持的后端用于缓存淘汰；SGLang 需启用 --radix-eviction-policy priority。
  • 设计方向：差异化管理标注块原文提出未标注块采用 LRU，带保留指令的块进入优先级结构；进一步将优先级、生命周期及放置意图传播至共享层。
  • 请求级、区间级与集群级语义分离TRT-LLM 的 token-range retention 属于引擎原语，不代表 Dynamo 已提供统一的区间 / TTL 接口或跨集群块租约。
接口限制nvext.cache_control 不是可用的 TTL pinning 接口；兼容 Anthropic cache_control 标注不意味着实现相同的自托管保留语义。
原文：Selective Cache Retention · 后端边界：priority 参考

方案 S5.2 / KV CACHE · 对应 P5 跨层生命周期控制属探索方向

生命周期驱动的私有 KV 回收与写入抑制

结合分支终止、历史压缩与共享引用信息识别失效状态，在不影响有效前缀的前提下减少无效驻留及跨层写入。

  • 通过生命周期事件识别 ephemeral KV子 Agent terminate、会话 compaction，以及不再进入后续输入的 thinking 内容，都可能使部分 KV 失去复用价值。
  • 降低失效私有块的保留与写入优先级原文探索 session 标记与引擎语义检测：优先回收已失效的私有后缀，并在适用时抑制其向共享存储写入。
  • 以有效引用约束回收范围回收需保留其他 Agent 仍使用的公共前缀；历史只要仍参与后续 attention，就不能仅依据当前请求完成而删除。
实现边界会话标识与路由亲和性不等同于跨层生命周期回收；精准失效识别、共享引用处理及写入抑制仍需引擎和存储协同。

请求语义、任务调度与状态生命周期协同

以编码 Agent 的多轮执行为例，将五类问题映射至对应处理层；收益来自跨层信息与数据路径的一致性。

  • P1 → S1：请求语义与元数据传递Frontend 归一多协议内容，稳定交互历史；Harness 通过 priority、osl 和预热提示提供任务级决策依据。
  • P2 → S2：放置与关键路径调度Router 联合评估前缀命中与活跃负载，跨队列传递优先级，并按会话连续性、并发度及容量约束适配策略。
  • P3–P5 → S3–S5：状态复用与生命周期共享路径扩展 KV 可访问范围；预热 / 预取降低恢复延迟；选择性保留与生命周期回收区分有效状态和失效私有状态。
优化目标减少冗余 Prefill、关键分支排队、暴露的状态恢复延迟及无效 KV 驻留；各项收益受后端能力与集成完整性约束。
